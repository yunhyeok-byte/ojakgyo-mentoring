## 1 MVP 이해하기

### MVP는 무엇인가요

MVP는 Minimum Viable Product의 약자로, **목표 고객에게 핵심 가치를 제공하면서 중요한 가설을 시험할 수 있는 최소한의 제품·서비스**입니다.

‘최소’는 기능을 적게 만든다는 뜻만이 아닙니다. 고객이 핵심 흐름을 끝까지 이용할 수 있어야 하고, 팀은 그 행동을 보고 다음 결정을 할 수 있어야 합니다. 일부 작업은 사람이 직접 처리해도 됩니다.

오작교의 핵심 흐름을 가정하면 ‘모임 조건과 출발지 입력 → 후보 확인 → 참여자와 공유 → 장소 선택’이 될 수 있습니다. 실제로 필요한 흐름은 오늘 정합니다.

| 구분 | 예시 | 확인할 수 있는 것 |
| --- | --- | --- |
| 화면 시안 | 추천 화면을 보여주고 이해되는지 질문 | 화면 이해도와 사용성 |
| 기술 시험 | 주소를 좌표로 바꾸는 API 호출 | 특정 기술의 구현 가능성 |
| MVP | 실제 모임의 조건을 받아 후보를 제공하고 장소 결정까지 관찰 | 고객에게 도움이 되는지와 사용 중 막히는 부분 |
| 확장 제품 | 계정 복구, 프로필, 알림, 모임 이력까지 제공 | 더 넓은 사용 상황과 운영 요구 |

화면 시안과 기술 시험도 유용합니다. 다만 지도 표시나 서버 배포가 성공했다는 사실만으로 고객의 장소 선정 문제가 해결됐다고 판단하지 않습니다.

### 지불의사는 사용 가치와 별도로 확인하세요

편리해도 돈을 내지 않을 수 있습니다. 무료 이용 가치가 있다는 사실과 수익모델이 성립한다는 사실을 구분합니다. 직접 과금이 어렵다면 다른 지불 고객을 가설로 탐색할 수 있지만, 제휴 매장이 비용을 낼 것이라고 자동으로 가정하지 않습니다.

먼저 제공 범위와 과금 단위를 구체적으로 설명한 후 질문합니다.

3. 어떤 조건이 충족돼야 비용을 내겠나요? 지금 쓰는 방법과 비교해 주세요.

> 작성:

## 멘토 진행 메모

활동 1은 장소 결정의 가치를 검증하려는 목적에서 C가 가장 직접적입니다. B도 중간 지점 확인 자체가 핵심 가치인 고객에게는 MVP가 될 수 있으므로, 기능 수보다 검증하려는 가설과의 연결을 설명하게 합니다.

팀이 기능 목록만 이야기하면 ‘그 기능이 없으면 어떤 고객이 어떤 행동을 못 하나요?’라고 묻습니다. 중간 지점과 좋은 모임 장소를 같은 뜻으로 사용하면 이번 청량리 사례의 목적·예산·공간 조건을 다시 확인합니다.

직접 과금이 어렵다는 이유만으로 문제 자체가 없다고 결론 내리지 않습니다. 문제의 존재, 해결책의 가치, 사업모델은 구분해서 검증합니다. 캡스톤에서는 구현과 설계·검증 경험을 성과로 남기고, 창업으로 이어갈 때 지불 고객과 비용 구조를 추가로 확인합니다.

오늘은 완성된 사업계획보다 하나의 실행 가능한 실험을 남기는 데 집중합니다. 다음 미팅에서는 화면 수보다 고객이 실제로 한 행동, 예상과 달랐던 점, 바꾼 결정을 확인합니다.
